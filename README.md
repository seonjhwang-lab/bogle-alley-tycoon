## v2.2 패치 (모바일 UX)
| 문제 | 원인 | 해결 |
|---|---|---|
| 왼쪽에 검은 여백, 화면이 오른쪽으로 쏠림 | ① 240×426 고정 비율이라 폰 화면이 9:16보다 짧으면 높이에 맞춰 축소 → 좌우 여백 ② `#game`의 flex 가운데 정렬과 Phaser `CENTER_BOTH`의 여백(margin-left)이 **이중으로** 적용되어 캔버스가 오른쪽으로 한 번 더 밀림 (360×520 실측: 왼쪽 50px / 오른쪽 17px) | ① 세로 해상도 = `floor(240 × 화면높이 ÷ 화면너비)`, 340~520 클램프 → 가로가 항상 화면 끝까지 ② flex 제거, `html/body/#game` margin·padding 0 · 100% · overflow hidden. 정렬은 Phaser에만 맡김 ③ HUD·카운터·주방·손질대 Y 좌표를 계산된 높이로 배분, 배경은 반복 타일 + 원본 아트 조각으로 조립 |
| 슬러시를 누르는 엄지가 컵·게이지를 가림 | 기계 자체를 누르고 있는 방식 | **오른쪽 끝 레버를 아래로 당기기.** 왼쪽 = 게이지 + 기계 + 컵(손가락이 닿지 않음), 오른쪽 = 레버 트랙 + 빨간 손잡이. 당긴 깊이로 속도 조절, 손을 떼면 '철컥!' 복귀 + 즉시 서빙 |

세로 높이 배분(남는 높이를 이 순서로): 주방 칸 +20 → 하단 안내 줄 +18 → 카운터 +44 → 나머지 3등분.
안내 줄이 들어갈 자리가 없는 짧은 화면(세로 < 358)은 안내 문구를 주방-손질대 경계의 토스트로 띄운다.
영업 중 화면 크기가 바뀌면 FIT으로 전체가 보이게 유지하고, 타이틀 화면에서만 레이아웃을 다시 계산한다.

## v1 → v2 무엇이 바뀌었나

| v1 문제 | 원인 | v2 해결 |
|---|---|---|
| 물이 끓는데 면이 안 들어감 | `[면+스프]` 버튼이 “선택된 냄비”를 우선 → 방금 물 부은 냄비(가열 중)로 면이 들어가고, 이미 끓는 냄비는 그대로 졸아 탐. 물 붓는 0.35초 동안의 냄비는 대상에서 빠짐 | 하단 버튼 삭제. **냄비 자체를 탭** — 그 냄비의 상태만 보고 행동 결정. 가열/끓음 어느 시점이든 면은 무조건 들어감 |
| 화면이 조잡함 | 180×320에 골목 뷰·주문·냄비·버튼 5개 | 240×426, 골목 보행 제거, 그림 레시피 카드 + 카운터 손님(2배 스프라이트) |
| 플레이 방법을 모름 | 처음부터 전부 열림 | Day 1 손가락 가이드 튜토리얼 + Day별 해금 팝업 + 첫 등장 힌트 |

## 조작 (v3.0)

- **냄비 탭**: 빈 냄비 → 물 붓기 / 가열·끓음 → 면 넣기(초록 골든타임이면 PERFECT) / 완성(READY) → **집기**(초록 테두리) → 손님 탭으로 서빙 / 탄 냄비 → 3번 탭 닦기
- **휴지통**(냄비 오른쪽 아래): 언제든 비우기
- **토핑**(계란·썬 대파·치즈): 재료 탭 → 노란 테두리 + 넣을 수 있는 냄비(익는 중·완성) 위에 `넣기` 화살표 → 냄비 탭. 냄비가 1개여도 자동으로 들어가지 않음. 완성된 라면에도 추가 가능. 6초 뒤 자동 취소
- **도마**: 3번 탭(명품 식칼: 1번) → 썬 대파 1인분
- **슬러시**(Day 3~): 오른쪽 빨간 레버를 **아래로 당기기**(15% 이하 정지, 깊을수록 빠름, 끝까지 약 1.1초) → 초록(80~92%)에서 놓으면 PERFECT → 컵 탭 → 손님 탭. 컵 옆 휴지통으로 버리기. 100% 넘으면 넘침 → 2초 뒤 컵 2번 탭으로 닦기
- **떡볶이 철판**(Day 3~): 윤기 날 때 철판 탭 → 손님 탭(종이컵 1컵). 졸면 좌우로 문지르거나 국자 버튼
- **어묵탕**(Day 4~): 빈 어묵탕 탭 → 2.5초 → 탭 → 손님 탭(꼬치 1개)
- **싱크대**(Day 4~): 3번 탭 = 그릇 1개. 깨끗한 그릇이 없으면 라면 서빙 불가(냄비는 그대로 들고 있음)
- **도둑고양이**(Day 5): 손질대 스테이션을 깔고 앉음 → 탭해서 쫓기. 방치해도 5초 뒤 떠남
- 주문하지 않은 메뉴를 손님에게 주면 거절되고 계속 들고 있음

## 검증 (헤드리스 Chromium)

`tests/` 스크립트는 `npm run dev` 상태에서 `puppeteer-core` + Chromium으로 실행한다.

- `verify.mjs` — 55개 항목: 프롤로그 컷신, Day 1 튜토리얼 2단계 서빙 가이드, 냄비 1개여도 재료 탭 → 냄비 탭으로만 투입(READY 라면에도), 완성 냄비 → 2번/3번 슬롯 특정 손님 서빙(탭·드래그·카드 탭), 주문 안 한 손님 거절, 슬러시 레버 → 완성 컵 대기 → 4번 슬롯 손님 / 휴지통 / 드래그, 떡볶이 윤기·졸음·젓기·리필·탐, 어묵탕 조리·지정 서빙, 그릇 없을 때 서빙 막힘, TV·오락기 6프레임 애니메이션과 효과, 히든 1·2 해금·클리어·별 4/5개, 무한 모드 (`VP=360x520 node tests/verify.mjs`처럼 뷰포트 지정)
- `viewport.mjs` — 360×640 / 360×520 / 390×660 / 412×700 / 390×844에서 캔버스 좌우 여백·가로 스크롤 측정 + 타이틀·Day 3 인트로·레버 가이드·레버 당기는 중 스크린샷
- `stress.mjs` — Day 5에서 3배속으로 무작위 탭·연타·드래그·레버 흔들기 → 탭만으로 모든 냄비·슬러시 복구 → 4개 냄비 풀사이클 확인
- `bot.mjs` — 2단계 조작으로 자동 플레이해 스테이지별 매출 측정 (`STAGES=d1,d3,h2 node bot.mjs none 0.8 250`, 업그레이드 `none|all|props|full`)

## 에셋

`public/assets/sprites/*.png + *.json` (Aseprite JSON, frameTags = 애니메이션 키). Phaser는 `load.aseprite()` + `createFromAseprite()`로 태그 이름을 그대로 애니 키로 쓰고, 정지 아이콘은 `ui/Frames.ts`의 `icon(scene, x, y, '태그')`로 꺼낸다.
시트: pot_modular · slush_machine · peeps(어린이·여학생·선생님·여고생·유도부원·고양이) · ui_icons(47) · ui_mini · shop_bg · kitchen_bg · prep · frontbar(철판·떡볶이 4상태·어묵탕) · props(미니 오락기 6f · 브라운관 TV 6f) · portraits(스토리 초상화 4명).
PC의 Aseprite 작업 폴더(`aseprite-mcp/workspace/bogle/`)에 같은 이름의 `.aseprite`(프레임·태그·프레임 시간 포함)와 `export/*.png|json`이 동기화되어 있다(내보낸 시트가 이 저장소의 PNG와 픽셀 단위로 일치하는 것 확인).
폰트: 갈무리(Galmuri) 7/9/11 Bold, OFL-1.1 (`public/fonts/OFL-Galmuri.md`).
